## Recovery

If source or UI activation fails, disable the web flag, restore the prior compatible API source/runtime and restart API 8010; leave the additive table dormant so any legitimate new observations survive. If the offline migration fails, its transaction rolls back and the protected backup remains available. A full database restore requires API stopped, a separately reviewed recovery decision, checksum/integrity verification, quarantine of the current database and sidecars, and proof that newer owner activity will not be overwritten. Never restore an old financial database simply to undo a source or flag change.
